# 标注项目 SOP

版本：v1.0（2026-11-18）　适用范围：数据标注类项目的标准执行流程。

## 1. 角色与职责

| 角色 | 职责 |
|---|---|
| 标注员 | 按 SOP 与规范执行标注，100% 自检后提交 |
| 质检（QC） | 抽检（≥10%）、返修判定、质量周报 |
| 仲裁 | 双人冲突复核，结论留痕 |
| 项目负责人 | 规范版本管理、试标组织、客户对齐 |

## 2. 执行流程（7 步）

1. **需求确认**：任务目标、验收口径、交付格式（JSON Schema）、排期与人力；输出《需求确认单》。
2. **规范宣贯**：规范版本号锁定，讲解红线条款与易错点；所有疑问记录进 FAQ，FAQ 与规范同版本号。
3. **试标**：每人试标 20 条，覆盖各难度与边界类型。
4. **一致性校验**：试标双人背靠背比对，Kappa ≥ 0.75 才转正式；未达标先排查规范歧义（归因三问），补训后二次试标。
5. **正式标注**：按配比表领任务；单批不超过 200 条，防止疲劳导致尾批质量下滑。
6. **自检与抽检**：标注员按《质检清单》100% 自检；QC 抽检 ≥ 10%，覆盖每名标注员、每个批次与全部边界类型。
7. **返修闭环**：抽检不合格整批退返；返修项记录进 badcase 库，同类 ≥ 3 次触发规范补丁。

## 3. 质量红线（抽检单条命中即整条返修）

- 事实编造、名称过时未修正；
- 安全内容未按边界处理；
- 多轮状态与上下文冲突；
- `quality_check` 字段与实际不符。

## 4. 工时与质量的平衡

赶工优先级：**自检 > 抽检覆盖 > 单量**。宁可少标 10%，不允许不自检交付——返修成本是首次成本的 2–3 倍，且污染一致性数据。

## 5. 变更管理

- 规范变更 = 版本号 +1，重大变更（红线、字段、判定标尺）需：公告 → FAQ 更新 → 全员重新试标 → 达标后恢复正式。
- 数据集版本与规范版本对齐，交付单注明 `dataset vX.X / guideline vX.X`。

## 6. 数据安全

- 客户数据不出域：标注环境离线或经网关审批；禁止拷贝到个人设备。
- 交付数据含个人信息的必须脱敏（手机号、证件号、住址），脱敏规则与客户书面确认。
- 项目结束后按合同约定清理本地数据并留清理记录。
