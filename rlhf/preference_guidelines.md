# RLHF 偏好标注规范

版本：v1.0（2026-11-18）　适用范围：同提示下两个模型回复的偏好比较标注。

## 1. 核心原则

1. **以指令为准**：判定标准是「哪个回复更好地完成了这条指令」，不是哪个更符合你的口味。风格差异（简洁 vs 详尽）若都能完成任务，不构成偏好依据。
2. **忽略无关差异**：与任务无关的差异（称谓、排版细节、无实义的客套话）不参与判定。
3. **一票否决**：任一回复出现严重事实错误（编造数据、张冠李戴）或安全隐患，无论其他维度多好，直接判负，并在 reasons 中标明 `一票否决`。
4. **依据必须落在文本上**：归因要引用回复中的具体内容，禁止只写「A 更好」。

## 2. 评估维度定义

| 维度 | 定义 | 常见扣分点 |
|---|---|---|
| 事实准确性 | 陈述与客观事实、公认知识一致 | 编造数据、名称过时、张冠李戴 |
| 指令遵循 | 满足指令的显式要求（字数、格式、角色、要点数） | 超字数、漏要点、格式不符 |
| 完整性 | 覆盖任务所需的关键信息面 | 漏答子问题、只答一半 |
| 逻辑连贯 | 论述自洽、推理链条完整 | 前后矛盾、结论与论据脱节 |
| 安全合规 | 无有害输出；拒答边界恰当 | 有害内容、过度拒答、拒答不足 |
| 语言表达 | 通顺、得体、无错别字 | 语病、错别字、语域错位 |

## 3. 判定标尺（5 级）

| 档位 | 含义 |
|---|---|
| A 显著优 | A 在至少一个关键维度明显更好，且无关键维度劣势 |
| A 略优 | A 整体略好，差距需要对照才能看出 |
| 相当 | 关键维度无实质差异（默认输出「相当」需写出两边的等价点） |
| B 略优 | 同「A 略优」 |
| B 显著优 | 同「A 显著优」 |

拿不准时降一档（显著优 → 略优），而不是平票。

## 4. 位置偏差控制（强制）

- 每组标注完成后执行 **AB 交换复评**：在心中把两个回复交换位置再判一次；交换后结论翻转的，说明你的判断受了位置影响，需重新归因后再提交。
- `swap_recheck` 字段必须为 true 才算完成标注。
- 抽检中若发现偏好与位置强相关（同侧率 > 70%），整批退回重标。

## 5. 一致性与仲裁

- 5–10% 任务双人背靠背标注，Kappa ≥ 0.75 达标。
- 双人不一致（显著优 vs 略优可接受；方向相反不接受）提交仲裁：由资深标注员按本规范复核并留痕。
- 仲裁结论若暴露规范歧义，走规范变更流程（见 SOP），不得私改口径。

## 6. 输出格式（preference_samples.jsonl）

```json
{"id":"pref-001","prompt":"…","response_a":"…","response_b":"…","preferred":"A|B|相当","swap_recheck":true,"key_dimension":"维度名","reasons":{"维度名":"引用文本的归因"}}
```

- `preferred` 必须来自标尺五档之一；`reasons` 至少包含关键维度与其他受影响维度的归因。
